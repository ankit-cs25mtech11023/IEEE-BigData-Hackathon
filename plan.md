# FinReason Cup 2026 — Task 1: Verifiable Financial Chain Reasoning

## Overview

Competition: FinReason Cup 2026 (IEEE Big Data Cup 2026, Challenge 03).
Site: https://the-finai.github.io/IEEE-bigdata-cup/ — Task 1 hub: `/task1/`.

Goal: for each templated financial word problem, output
1. `final_answer.value` — typed answer (decimal with stated rounding, or enum `true`/`false`), and
2. `steps` — exact values for every published intermediate "slot" in `trace_spec`.

Facts established from data and scorer:
- 290 templates × 10 instances in train; 12 domains, 58 topics; difficulty basic/intermediate/advanced.
- Answer types: decimal (93%) and enum (7%). Units: usd, percent, usd_million, multiple, ratio, days, ….
- Slots per question: 0–3. Slot values are `exact` (no rounding); rational strings like `1975/28` are accepted.
- Question text may itself contain rationals (e.g. `1975/28`).
- **Scoring is exact match, no tolerance.** Final: both values quantized with the stated rounding then compared. Slots: exact rational equality.
- Final-answer score (FAC) and step score (checkpoint) are reported separately; ranking = FAC first, then checkpoint.
- **Official test score = (seen_score + hidden_score) / 2.** Test = 580 *seen* (train templates) + 348 *hidden* (new templates; only intermediate/advanced).
  Within a stratum, scores are macro-averaged template → (domain, topic, difficulty) cell → topic with difficulty weights
  (seen: basic 0.4 / intermediate 0.4 / advanced 0.2; hidden: intermediate 0.5 / advanced 0.5).
- Text-skeleton matching: 571/580 leaderboard and 560/928 test questions match a train skeleton exactly → leaderboard is effectively seen-only, test has ~350 hidden-template questions.
- Dev leaderboard baselines (seen-only): Advanced 0.984 / 0.990, Standard 0.981 / 0.988, Lite 0.234 / 0.555, rule-based 0.021 / 0.012.
  ⇒ seen half is near-saturated for strong systems; **the hidden half decides the ranking.**
- Rules: LLMs / external models allowed. No registration. No code/weights required at submission.

## Approach

Two-path router per question:

1. **Seen path (template solvers).** For each of the 290 train templates, a deterministic Python solver
   `solve(question_text) -> {final, slots}` that parses numbers from the text and computes with `Fraction`.
   Solvers are generated by the LLM from the template's train instances + gold, then **accepted only if they
   reproduce gold on all train and dev instances of that template** (exact). Failures are retried / fixed by hand.
   Routing: question → template via text skeleton (numbers masked) + answer/trace-spec signature, with nearest-skeleton fallback.

2. **Hidden path (program-of-thought + self-consistency).** For questions with no verified solver:
   LLM receives question, `answer_spec`, slot descriptions, and k retrieved similar train examples (question + gold
   + verified solver code). It writes a Python program using `Fraction` that returns final and slot values.
   Program runs in a sandbox (timeout, restricted builtins). Sample N programs, majority-vote on the final value,
   then vote slots among programs agreeing with the winning final. Formatting/rounding is done by our code, never the LLM.

3. **Fallback.** If nothing works: abstain (`final_answer: null`, empty steps) — valid and scores 0 rather than failing the upload.

Evaluation:
- Seen path: official scorer on local dev (290) + leaderboard uploads (580).
- Hidden path proxy: **leave-template-out** on train/dev intermediate+advanced templates (no solver, no same-template few-shot).
  This is the only local signal for the half of the score that matters most.

## Key Decisions
- 2026-10-05: Target Task 1 only (live, clean data; Task 2 scorer unpublished, Task 3 more complex).
- 2026-10-05: Arithmetic always in Python `Fraction`, never by the LLM — scoring is exact match with no tolerance.
- 2026-10-05: LLM = college-hosted open model via OpenAI-compatible API (no local GPU on dev laptop). Prefer largest instruct/coder model (≥32B; 70B+ ideal). Model chosen empirically on dev.
- 2026-10-05: Seen path uses verified per-template solvers; hidden path uses PoT + self-consistency. Hidden half = 50% of final score, so most effort goes there after seen path is solid.
- 2026-10-05: Use system Python 3.14 in a venv (official scorer verified on 3.14); avoid extra tooling.
- 2026-10-05: Git local only until user confirms remote; commits under user's identity, no AI attribution.
